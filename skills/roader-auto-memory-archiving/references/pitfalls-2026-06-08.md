## 🔴 P0 严重：skill_manage action='create' 假成功

**日期**：2026-06-08
**触发场景**：第一次建 `hermes-auto-memory-archiving` skill
**症状**：
```json
{"success": true, "message": "Skill 'hermes-auto-memory-archiving' created.", ...}
```
但 `skill_view(name='hermes-auto-memory-archiving')` 立即报 `Skill not found`。

**根因（推测）**：profile 索引与文件系统不同步，或缓存未失效。

**修复（已加到 `Roader-skill-creator` skill）**：
- `create` 之后**必须** `skill_view` 验证
- 找不到就用 `skill_manage action='write_file'` 兜底直接写 `SKILL.md`
- 永久规则：**永远信任 skill_view 的返回，不信任 create 的 success**

**教训**：
1. 任何"创建成功"消息都不能立即告知用户已存
2. 必须有二次验证
3. 后续所有 skill 创建都用 `write_file` + `skill_view` 双保险

## 🟡 P1 中等：smart_archive.sh 标签优先级 bug

**日期**：2026-06-08
**触发场景**：归档 daily 快照时，标题含 "NAS" 项目名
**症状**：`smart_archive.sh "...$" "...$" "daily"` 把归档丢到了 `projects/NAS/` 而不是 `daily/`

**根因**：
旧版 `resolve_category` 的 case `""|"daily"` 把 daily 标签丢进了"检查项目名 → 启发"分支，导致项目名归并逻辑先于 daily 标签执行。

**修复（已上线）**：
```bash
case "$tag" in
  "preferences"|"incidents"|"daily")
    echo "$tag"
    return
    ;;
  "")
    # ... 启发式逻辑
    ;;
  *)
    echo "projects/$tag"  # 当项目名
    ;;
esac
```

**硬规则**：`preferences` / `incidents` / `daily` 三个标签**绝对保留**，绝不走项目归并。

**测试**：
```bash
# 复测：故意传 daily 标签 + 含 NAS 关键词的内容
smart_archive.sh "测试" "正文提 NAS" "daily"
# → 必须落到 daily/，不是 projects/NAS/
```

## 🟡 P1 中等：smart_archive.sh 项目名拆分 bug

**日期**：2026-06-08（首次测试发现）
**触发场景**：建 `projects/3D打印/` 项目后，再归档"3D打印材料对比"
**症状**：被拆成两个项目 `projects/我的新玩具：3D/` + `projects/3D打印材料对比/`

**根因**：
旧版用 `cut -c1-6` 取项目名短词，遇到中文+数字混排时拆错：
- "我的新玩具：3D打印小恐龙" → 短词 "我的新玩"
- "3D打印材料对比" → 短词 "3D打印"

**修复（v2）**：
- 用 `cut -c1-4` 取更短的关键字
- **接受归并不强制**——用户说"这个不是同一项目"再手动移

**硬规则**：项目名要让 Hermes 自己起，**短而独特**（不超过 8 字符）。

**最佳实践**：
```bash
# ✅ 好
smart_archive.sh "..." "..." "3D打印"        # 6 字符
smart_archive.sh "..." "..." "NAS"            # 3 字符

# ❌ 差
smart_archive.sh "..." "..." "我的新玩具3D打印小恐龙"  # 12 字符，易冲突
```

## 🟡 P1 中等：Obsidian vault 注册表坑

**日期**：2026-06-08
**触发场景**：Obsidian 装好后用户反馈"啥也看不到"
**症状**：
- Obsidian 进程在跑（4 个）
- `~/HermesMemory/` 有 22 个文件
- 但 Obsidian 界面里文件树是空的

**根因**：
Obsidian 默认打开了 `~/Documents/Obsidian Vault`（系统空 vault），不是新建的 HermesMemory。Obsidian 有独立的 vault 注册表 `obsidian.json`，不注册就不显示为可选 vault。

**修复（4 步）**：
1. 退出 Obsidian
2. 编辑 `~/Library/Application Support/obsidian/obsidian.json` 在 `vaults` 里追加新 vault
3. 重启 Obsidian
4. `open "obsidian://open?vault=<id>&path=README.md"` 触发打开

**详细步骤** → `references/obsidian-vault-setup.md`

**教训**：
- 装好新软件后**第一件事**是验证默认状态是不是预期状态
- 看到"啥也没有"先怀疑默认配置，不要先怀疑"我哪里错了"
- obsidian.json 路径固定，cat 一下就能查

## 🟡 P1 中等：brewing 已装但 PATH 不通

**日期**：2026-06-08
**触发场景**：用户提醒"我装了 brew 啊"
**症状**：
- `brew` 命令 not found
- 但 `/opt/homebrew/bin/brew` 存在
- 实际 brew 5.1.14 已装

**根因**：brew 装在 `/opt/homebrew/bin/`，但用户的 PATH 没包含这个路径

**修复**：
- 短期：用绝对路径 `/opt/homebrew/bin/brew <cmd>`
- 长期：用户确认后 `echo 'export PATH="/opt/homebrew/bin:$PATH"' >> ~/.zshrc`

**教训**：
- 找不到命令时**先查绝对路径**（`ls /opt/homebrew/bin/brew /usr/local/bin/brew`）
- 不要直接判定"没装"
- PATH 修改要用户确认（dotfile 改动）
