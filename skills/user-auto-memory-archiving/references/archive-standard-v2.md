# 归档标准 v2 — 什么该归档 / 什么不该归档（2026-08-15 用户拍板）

> 触发：用户投诉「记忆系统只有标题没有实质内容」「两个月的实质工作基本缺失」。归档必须让之后查冷记忆能直接答出「完成了什么、产出了什么」。

## ✅ 该归档的（有实质成果）

1. 完成了什么（项目/任务/功能）
2. 产出了什么（可交付物：文件/代码/报告/图片路径）
3. 踩了什么坑（值得记录的教训）
4. 修复了什么（bug/问题/错误，含根因）
5. 做了什么决策（影响后续的选择）

## ❌ 不该归档的（流水账）

1. "读了什么文档" — 除非读完直接产出成果
2. "确认了什么规则" — 除非是修复了规则的 bug
3. "验证了什么功能" — 除非验证发现了问题
4. "查了什么资料" — 除非查完直接写了报告

## 📝 归档格式（强制，smart_archive.sh 会检查）

```markdown
# 标题（说清干了啥）

## 摘要
一句话说清楚：完成了什么 + 产出了什么。（必须存在且 ≥10 字符，否则 smart_archive.sh exit 1 拒写）

## 完成内容
具体做了什么，分点列出。

## 产出物
可交付的文件/代码/报告路径。

## 关键决策（可选）

## 踩坑教训（可选）
```

## 🔍 判断标准

**问自己：之后用户问"xxx做了吗"，我能从这条归档里直接答出来吗？**

- ✅ 能 → 该归档
- ❌ 不能 → 不该归档

## 🎯 执行规则

1. 项目收尾时**由机制触发**归档（auto-archive plugin / smart_archive 摘要门禁），不靠 agent 记性
2. 只记有实质成果的，机械工作不记
3. 必须写摘要，一句话说清干了啥
4. 必须列产出物，可交付的文件路径
5. 踩坑必记，这是最有价值的

## 示例对比

### ❌ 错误示例（流水账）
```markdown
## 完成工作
- 读完 AGENTS.md
- 读完周报 HTML
- 确认 SOP
```

### ✅ 正确示例（有成果）
```markdown
## 摘要
接手 AI特攻队项目维护工作，完成课题7推广海报终版 + 高清图。

## 完成内容
1. 项目接手：通读 AGENTS.md，掌握周报/海报 SOP
2. 课题7海报：从课题1科技风 v2 复制，生成终版 HTML + 高清图（2382×4026）

## 产出物
- 课题7推广海报_科技风_v3_终版.html
- 课题7推广海报_科技风_v3_高清图.png
```
